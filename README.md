# Tasks Lite

本地 CalDAV 待办客户端。数据直接存在你自己搭的 CalDAV 服务器上，**不经过任何第三方云服务**。

![stack](https://img.shields.io/badge/Electron-44-47848F) ![license](https://img.shields.io/badge/license-MIT-green)

---

## 为什么做这个

Tasks.org 的桌面版和 Android 版都把「自托管 CalDAV 同步」放在付费档里（最低 $0.99/年），而 CalDAV 服务端（Radicale）本来就完全免费开源。既然协议是开放的，就没必要为了同步自己的服务器付订阅费。

这个客户端：

- 只连你自己的 CalDAV 服务器，不碰任何第三方账号体系
- 密码用 Windows **DPAPI** 加密后存本地，只有当前 Windows 用户能解开
- 服务器是权威数据源，本地缓存只为「断网也能看」服务
- 单文件 exe，双击即用，不用装 Node、不用装运行时

## 功能

- **托盘常驻**：关窗口只是缩到右下角托盘，程序继续在后台同步
- **全局快捷键** `Ctrl+Shift+T` 唤起/隐藏，不需要先找到窗口
- **开机自启**（可开关）：开机直接进托盘，不弹窗口
- **主题**：浅色 / 深色 / 跟随系统，外加自定义强调色（即时生效、自动保存）
- **今天**：手动把任务收进「今天」清单，列表行点 ☀ 就能加/移出，一直保留到做完
- **四象限**：按「重要（高优先级）× 紧急（今天到期）」自动分四组，没完成的一眼看完
- **日历**：月视图 / 周视图，点某天筛出当天的任务，点任务条直接进编辑区
- **日历里直接加待办**：月视图格子右上角、周视图每列底部都有 `+`，点开输入框回车就在那一天建一条，支持 `!高` `#标签` `@清单` 那套语法
- **Windows 系统通知**：到点在右下角弹出通知中心的原生 Toast，点通知直接跳到那条任务；系统不支持时退回托盘气泡。设置里可以点「发一条测试通知」当场验证
- **智能快速添加**：输入框里直接写 `明天交房租 #房租 @财务 !高`，回车自动拆成标题/日期/标签/清单/优先级，输入框下方有实时解析预览
- **步骤**：任务内的可勾选清单，行上显示 `☑ 2/5`
- **子任务**：任意层级，在任务编辑区的「上级任务」里指定，列表里自动缩进
- **循环任务**：每天 / 每周 / 每个工作日 / 每月 / 每年，也能手写任意 RRULE；**勾完成后自动生成下一条**，老的那条留档为已完成
- **提醒**：到点弹 Windows 通知，点通知直接跳到那条任务
- **列表 + 标签**：侧边栏按列表和标签分组，点一下就能筛
- **智能筛选**：今天到期 / 本周内 / 未来 7 天 / 无截止日 / 高优先级 / 循环任务 / 有提醒 / 在今天 / 是父任务 / 是子任务
- **回收站**：误删能原样恢复（本地，不会上传到服务器）
- 新建 / 编辑任务，优先级（高 / 中 / 低）、截止日期、备注
- 勾选完成（带系统通知）
- 全文搜索
- 自动同步（间隔可配）+ 窗口聚焦即同步 + Ctrl+R 手动同步
- **加完任务自动补一次全量同步**：手机上刚改的、别的设备刚加的立刻反映到侧边栏和计数里（连着快速添加多条只触发一次）
- 断网时操作照常进行，联网后自动补传（乐观队列）

### 快速添加能认什么

| 写法 | 含义 |
|---|---|
| `明天` `后天` `大后天` `下周三` `本周五` `3天后` `月底` `11月5日` `11/5` `2026-12-25` | 截止日期 |
| `15:30` `下午3点` `晚上8点半` | 提醒时间 |
| `每个工作日` `每天` `每周` `每月` `每年` | 循环规则 |
| `#标签` | 标签 |
| `@清单` | 列表 |
| `!高` `!中` `!低` `!1` `!5` `!9` | 优先级 |

解析不出修饰时整句当作标题，**绝不吞字**。

### 退出方式

关窗口 ≠ 退出。要彻底关掉请用**托盘图标右键菜单里的「退出」**，或 `Ctrl+Q`。

## 使用

1. 双击绿色版 exe 或运行安装包
2. 点右上角 ⚙ 填服务器信息：

   | 字段 | 值 |
   |---|---|
   | 服务器地址 | `https://你的服务器/你的用户名/` |
   | 用户名 | `你的用户名` |
   | 密码 | 你自己的 |
   | 自动同步间隔 | 任意（分钟） |
   | 连接方式 | 默认「直连」，见下 |

3. 点「测试连接」，看到"连接成功，发现 N 个日历"就成了
4. 点「诊断连接」可以看实际走没走系统代理、服务器返回什么、多久
5. 点「保存」

外观在同一面板下半部分的「外观」区域设置，**不用点保存，选了立刻生效**。

### ⚠️ 服务器地址必须带用户名

必须是 `https://主机/用户名/` 这种 **principal 路径**，不能只写域名根路径。

原因：CalDAV 规范里根路径只是 collection 不是 principal，不提供 `calendar-home-set` 属性（会返回 404）。Task.org 一类客户端直接在入口 URL 上取这个属性，拿到 404 就判定为「无效」。这个坑在调试 Task.org 时踩过，本客户端也做了规避 —— 即使入口 URL 取不到 `calendar-home-set`，也会回退用你填的 URL 本身。

### 连接方式：默认直连

CalDAV 请求**默认不走系统代理**。自己的服务器本来就能直连，绕代理既慢又会引入代理自己的错误状态码（比如莫名来一个 `402`）。

如果你必须通过代理访问服务器，在设置里把「连接方式」改成「跟随系统代理」，诊断按钮会显示实际路由。

## 技术实现

### CalDAV 协议

全部手写，没用第三方 DAV 库：

| 操作 | 方法 |
|---|---|
| 发现 principal / calendar-home-set | `PROPFIND` Depth:0 |
| 列日历 | `PROPFIND` Depth:1 |
| 建日历 | `MKCALENDAR` |
| 拉取全部任务 | `REPORT` calendar-query + VTODO filter |
| 新建/更新任务 | `PUT`（带 `If-Match` etag 乐观锁） |
| 删除 | `DELETE`（带 `If-Match`） |

认证用 Basic。任务实体是标准 iCalendar VTODO（RFC 5545），所以 Task.org、DAVx⁵ 等其它客户端能直接读同一个日历。

各功能对应的 ICS 字段：

| 功能 | 字段 |
|---|---|
| 子任务 | `RELATED-TO;RELTYPE=PARENT:<uid>` |
| 循环 | `RRULE`（FREQ / BYDAY 等，原样保留） |
| 提醒 | `VALARM` + `TRIGGER;VALUE=DATE-TIME`（也认别的客户端写的相对 `TRIGGER:-PT30M`，按截止日换算） |
| 标签 | 标准 `CATEGORIES`，别的客户端也认 |
| 列表 | `X-TASKSLITE-LIST`（iCalendar 没有"列表"这个概念，用自定义属性，不污染标准字段） |
| 今天 | `X-TASKSLITE-MYDAY`，值为加入日期 `YYYY-MM-DD` |
| 步骤 | `X-TASKSLITE-STEPS`，JSON 数组 |

> **`X-` 自定义属性必须自己转义。** 实测 ical.js 对标准 `SUMMARY`/`DESCRIPTION` 会正确转义 `,` `;` `\`，但对 `X-` 属性（type=unknown）**既不转义也不解转义**。所以 `X-TASKSLITE-*` 里的 `,` `;` `\` 走 `escapeText`/`unescapeText` 手工处理；标准属性一律交给 ical.js，多转一次会多一层反斜杠。
>
> 折行（RFC 5545 的 75 octet）经验证是安全的：vobject 按字符边界折行，中英文长文本都能完整往返，不用规避。

### 同步策略

同步模型是**本地优先 + 合并**，跟滴答清单那类成熟客户端一致：

1. **本地先落库**。新增/修改立刻写进本地库并标记 `dirty`（待上传），界面立刻响应，**不依赖网络**
2. **再推服务器**。推成功就清掉 `dirty`；推失败（断网/服务器抽风）就进待传队列，改动**留在本地**
3. **拉取是合并不是覆盖**。服务器是权威，但**本地还有没上传的改动时，服务器版本不能盖掉它** —— 只吸收服务器带来的 `href`/`etag`。否则用户改了一半还没传上去，一次全量拉取就把他的改动静默改回去了
4. **待传队列逐条管理**。推送成功才移除那一条；失败的那条留在队列里下轮重试。`markSynced()` 只记时间，**不清空队列**
5. **冲突自愈**。412/409 会重读服务器最新 ETag 再写一次（后写为准），连续冲突才保留在队列里等下轮

配套的两条：

- **退避重试**：推送失败后 10 秒重试，每次失败翻倍，封顶 5 分钟。网络一恢复就补传，不用干等下一个同步周期
- **状态可见**：右上角显示「待上传 N 条」，列表里每条未上传的任务带「待上传」徽章。你能一眼看出"我加的东西到底上去了没有"

清理服务器上已删除的任务（别的客户端删掉的）时，**标了 `dirty` 的、在待传队列里的、从没上传过的一律跳过**，只删真正两边都没有的。

> 离线时新加的任务**照样出现在列表里**（这是老版本最大的问题：推送失败时它只在队列里，界面根本不显示，刷新就没了）。

**删掉的任务不会"复活"**（v1.6.0 修的 bug）。断网时新建一条 → 顺手删进回收站 → 网络恢复，旧版本会把待传队列里那条 `put` 重放成功，任务重新出现在列表里，还会被真的 PUT 回服务器。现在：

- 删进回收站时，没传上去过的任务会**撤掉**待传队列里对应的 `put`（服务器上本来就没有它）
- 彻底删除、清空回收站，同样会撤掉待传操作
- 已经在回收站里的任务，任何写入路径都不会把它塞回任务列表（只更新回收站副本上的 `href`/`etag`）

### Windows 系统通知

到点的提醒走 Windows 原生 Toast（通知中心里能看到、能点开、点完直接跳到那条任务）。

要发得出「像系统应用」的通知，有个前提是 **AppUserModelID** —— 不设的话，Windows 不认这个通知是谁发的，可能干脆不弹，或者在通知中心里显示成 `electron.app.Electron`。所以主进程一启动就 `app.setAppUserModelId('local.gcaiso.taskslite')`。

系统完全不支持通知时（例如精简版系统），退回托盘气泡（`tray.displayBalloon`），那也是系统级的。设置面板里的「发一条测试通知」会告诉你实际走了哪条通道。

> 提醒是**程序在后台运行时**才发得出来的。程序完全退出后自然没有提醒 —— 这是所有本地待办客户端的共同限制，真要「关机也能提醒」得靠 Windows 任务计划程序那一套。

### 412 冲突自愈

同一个日历上有第二个客户端（手机、另一个窗口、Tasks.org）时，两边会拿着各自缓存的 ETag 去写同一条任务，后写的那个必然拿到 `412 Precondition Failed`。单纯把 412 抛给用户是没用的 —— 他什么也做不了。

所以本客户端的做法是**冲突了就自愈**：

- `PUT` 撞 412 → 重读一次服务器现状，拿最新 ETag 再写一遍（后写为准）；服务器上已经没有这条就按新建写
- `DELETE` 撞 412 → 重读 ETag 再删；服务器上已经被别人删掉（404）就当成功
- 重试上限 3 次，仍冲突才如实报错（错误信息会说明是冲突）
- 队列重放时遇到 `409`/`412` 会丢弃该操作，交给随后的全量拉取覆盖，避免死循环

### 回收站与提醒是本地的

回收站里的任务**不会上传到服务器**（服务器上确实删掉了），恢复时重新 `PUT`。这样就不会把一堆"已删除"的任务同步到 Task.org 之类的客户端里碍眼。代价是回收站内容只在本机，换设备看不到。

提醒的"已弹过"状态也存在本地，并单独放在 `reminded` 字段而不是任务里 —— 否则每次全量同步覆盖任务时，这个状态会被冲掉，导致同一个提醒反复弹。

## 开发

```bash
npm install
npm start              # 开发模式运行
npm test               # 本地单测（ICS 往返 + 缓存层 + 解析/RRULE + 412 自愈 + 渲染层自检）
node test/selftest.js  # 对真实 CalDAV 服务器做端到端自测（会写-读-删临时任务，需设 CALDAV_URL/USER/PASS 环境变量）
npm run dist           # 打包 portable + nsis
```

改完 UI 记得跑一下 `npm test` —— `scripts/check-dom.js` 会检查 `app.js` 里 `$('id')` 引用的元素在 HTML 里是否真的存在。本项目踩过一个相关的坑：`app.js` 顶层顺序执行，中间抛异常会导致后面的启动代码（包括绑定状态回调）全都不执行，界面一片空白但主进程毫无报错。

## 已知限制

- `RRULE` 只支持 `FREQ`/`INTERVAL`/`BYDAY`/`BYMONTHDAY`/`BYMONTH`，`COUNT` 和 `UNTIL` 不参与自动滚动
- 首次同步是全量拉取，任务量到几千条以上会变慢（家用场景无所谓）
- 换 Windows 账号后 DPAPI 解不开密码，需要重新填
